重点解释「为什么这么绕」：沙箱（66.13 上）不是不能出网，而是出口被上网认证网关 AC Portal 管控（HTTP 302 认证页 / 443 重签伪证书）。因此 pip 装包改走内网 devpi（136）——136 出口干净，能回源阿里云 PyPI；沙箱侧用 allow-out-cidr 192.168.10.136/32 只放行这一个内网目标，其它出网流量仍被 egress MITM（VeriSign 伪 CA）拦截，容器/agent 侧用 combined-ca.pem（mkcert + 系统根 bundle，约 148 证书）信任该 MITM，二者配合才是「能装包又可控出网」的完整方案（根因与 CA 细节见 .env.example:36-50 注释）。

3 · 数据流向（一次问答的完整链路 + 遥测三通道）

图 3A 是「用户问一句话」从请求到工具执行的主链路；图 3B 是链路产生的可观测数据（logs/metrics/traces）如何分三路落库与检索。
  1. 页面与鉴权：浏览器 GET http://10.10.10.67/ → Caddy :80 →（非 /api）geesun-agent-web:3000。登录走 LDAP/AD（agent 侧 ldap://192.168.1.241:389，DC=geesun,DC=li）或 JWT，前端 Token 存浏览器。
  2. 发消息：浏览器 POST /api/chat（SSE）→ Caddy 按 /api/* 转发 geesun-agent:8009（Caddyfile:15-17）。关键：/api/* 必须在 Caddy 直连后端，否则 Next.js 自身 rewrite 会形成回环（Caddyfile 头注释）。
  3. agent 编排循环（agent 内部，一次回答可能多轮）：LangGraph 状态机每步：取 checkpoint/记忆 → 调 vLLM 推理（OpenAI 兼容，base_url=http://172.16.66.13:8003/v1，model=Qwen3.6-35B-A3B，启用 auto-tool-choice）→ 若模型选择工具则执行 → 结果回填再推理，直到给最终答案。
  4. 工具执行去向（按工具类型）：MCP 工具 → geesun-mcp:8000/mcp（解密 DLP 文件、解析 uploads/reports、跑 skill）；代码/解析类 → cube-api:6000 起沙箱 VM（模板 dev-pipfix，缺包现场 pip → 136 devpi）；记忆读写 → agent-postgres:5432（checkpointer 每轮快照 + store 跨会话记忆）。
  5. 流式回传：SSE 通道全程回传 agent 的思考与工具输出（15s 心跳保活，避免代理 60s 空闲掐断）；web 不参与业务转发，仅 UI。
  6. 会话结束：异步触发可观测上报（traces → Phoenix + Langfuse；metrics → Prometheus；logs 由 Alloy 持续采集），见 3B。
两条 trace 通道并存（互为备份/互补）：Phoenix（C 通道，OpenInference 协议、经 Alloy 转发、侧重 agent 内部 span 因果）与 Langfuse（D 通道，直发、S3+队列落 ClickHouse、侧重 LLM 调用链路与成本）。otel_project_name=Geesun-Agent-prod。若 ClickHouse 长期 0 trace，先查 langfuse-worker 是否用错 web 镜像（BullMQ 无人消费），勿先怀疑链路（2026-09-03 实测坑，docker-compose.langfuse.yml:26-28 有注释）。
